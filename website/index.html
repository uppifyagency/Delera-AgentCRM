Proactive doesn't
mean permissionless.

An agent should reduce the work on your plate while keeping your customer relationships under your control.

Read the privacy boundaries ↗
↳

Local core, personal accounts.

SQLite holds the CRM records in your workspace. The starter ships without credentials or customer data.

↳

A draft is not a sent message.

Customer-facing sends, sharing and consequential changes need explicit approval. Uncertain outcomes are reconciled before retrying.

↳

Evidence before confidence.

Keep sources, versions and receipts. A listed connector isn't proof of access. A workflow definition isn't a running automation.

A FEW THINGS WORTH KNOWING

Before you begin.

Is this a hosted CRM service?

No. This website introduces the project. The CRM runs in your own compatible workspace, with your chosen agent. It is not an online dashboard, a managed cloud database or a 24/7 agent service.

Does it work with ChatGPT Work and Claude Cowork?

The starter includes instructions for both. The host needs persistent file access, command execution and Node.js 22.23+ in the 22.x series. Connector availability and permissions must be checked in each session. Separate end-to-end testing on new accounts is still required.

Are Google accounts already connected?

No credentials are bundled. The agent reuses verified connections in your host app. Missing connections need your authorization. A direct desktop OAuth path exists as an integration component, but is not a complete universal connector.

Will it send emails on its own?

Not from this starter. The generic live executor is disabled. Agent-assisted customer-facing actions require explicit approval under the operating policy.

Can I inspect or contribute to the project?

Yes, the source, tests, documentation and roadmap are public on GitHub. Read the contribution guide, keep examples synthetic and never include customer data, OAuth tokens or private workspace files.
